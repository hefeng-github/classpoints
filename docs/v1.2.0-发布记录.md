## 验收

发布工作流 12 个步骤全绿。发布后做了一次不带任何令牌的匿名验证：

```bash
curl -L -o m.json -w '%{http_code} %{size_download}\n' \
  https://cnb.cool/mmhf-me/classpoints-dist/-/releases/download/stable/release-manifest.json
# 200 606 字节；version 1.2.0、tag v1.2.0、channel stable

curl -L -o setup.exe -w '%{http_code} %{size_download} %{time_total}\n' \
  https://cnb.cool/mmhf-me/classpoints-dist/-/releases/download/v1.2.0/ClassPoints-Setup-1.2.0.exe
# 200 51466673 字节 10.4 秒；实算 SHA-256 与清单一致
```

清单地址会先 `302` 到对象存储再 `200`，客户端下载器必须允许自动重定向。

## 这次修掉的两个发布期 bug

两个都只在 GitHub 的 Windows runner 上复现，本地（中文系统、装了 Inno）跑不出来。

**一、`scripts/pack-installer.ps1` 找 ISCC 时把字符串当数组**

```powershell
$candidates = @(...) | Where-Object { $_ -and (Test-Path $_) }
if ($candidates) { return (Resolve-Path $candidates[0]).Path }   # 只命中一个时 $candidates 是字符串
```

管道过滤后只剩一个结果时 PowerShell 会把数组展开成标量，`$candidates[0]` 取的是首字符 `C`，
于是报 `Cannot find path 'D:\a\classpoints\classpoints\C'`。改为 `@($candidates)[0]`。

**二、`scripts/make-release-manifest.py` 打印中文摘要崩溃**

清单文件本身是以 `encoding="utf-8"` 写的，没问题；崩在最后几行 `print("版本 1.2.0")` ——
英文系统上 stdout 是 cp1252，`UnicodeEncodeError`。文件写好了却把整步弄红。
脚本开头把 stdout/stderr reconfigure 成 UTF-8，不依赖外部环境变量。

## 一个前提：分发仓库不能是空的

CNB 建 Release 需要 `target_commitish`，空仓库没有 `main` 分支，接口直接回
`400 {"errcode":2000002,"errmsg":"invalid commit revision main"}`。
所以分发仓库里放了一个 README 提交，仅此而已。

## 下次发版

GitHub Actions → release → Run workflow，填三段版本号（如 `1.2.1`）和更新说明。
它会先跑全部单测，再打包、生成清单、先传 `v<版本>` 标签、最后才覆盖 `stable`。

顺序不要改。清单先挂上去，客户端会立刻去下一个还不存在的安装包地址。
